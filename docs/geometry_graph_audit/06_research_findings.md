### Is the current data volume/annotation quality enough for a GNN? — No, and here's the reasoning

1. **No graph ground truth exists at all.** `05_testing_metrics_audit.md` confirms zero tests assert on edge correctness, and no hand-annotated node/edge dataset was found anywhere in the repository. A GNN needs exactly this — labeled nodes and edges at meaningful scale — before it can be trained or even evaluated.
2. **The graph itself is currently unreliable as a *source* of training signal.** Per `04_graph_audit.md`, edges are emitted from a list-order-windowed loop that silently misses spatially-proximate pairs, node IDs are non-deterministic, and the same relationship type is computed by two independently-thresholded code passes that can disagree. Training a GNN on today's graph output would mean learning to reproduce these artifacts, not the true underlying structure.
3. **The deterministic baseline hasn't been exhausted.** Several P1-level fixes above (spatial indexing, bipartite matching, typed edges, alternative-hypothesis retention) are cheap, explainable, and directly address the failure modes found in this audit — they should be done and measured *before* any learned component, both because they're likely to close most of the gap and because they'll make any future learned model's *input* graph trustworthy.
4. **Recommendation**: build the P1 deterministic improvements first, add the metric suite from `05_testing_metrics_audit.md` (especially edge precision/recall and association top-k recall) to measure the resulting graph quality, and only then evaluate whether a learned edge classifier (tabular, not a GNN) closes a real remaining gap. A GNN specifically should be revisited only after (a) a tabular classifier has been tried and shown insufficient, and (b) a genuinely large (hundreds+) hand-annotated graph corpus exists — which does not exist today.

## Do not recommend replacing deterministic geometry with an LLM

Per the guardrails, and independently confirmed by this audit: nothing in `03_geometry_audit.md`'s weaknesses table calls for natural-language reasoning — every finding (scale awareness, spatial indexing, line merging, region segmentation) is a classic computational-geometry problem with well-established deterministic or lightly-statistical solutions. An LLM would be slower, non-deterministic, harder to test, and would not out-perform an R-tree or a Hungarian assignment at tasks R-trees and Hungarian assignment are designed for.

## Summary recommendation ordering (detail in `08_prioritized_roadmap.md`)

1. Scale-aware tolerances (unlocks correctness of everything downstream)
2. Spatial indexing (STRtree/R-tree) replacing uniform grids and windowed loops
3. Typed evidence-graph vs. structural-hypothesis-graph separation, with NetworkX as the storage layer
4. Bipartite matching + explicit alternative-hypothesis retention at the graph layer
5. A proper geometry/graph metric suite and hand-annotated ground-truth set (prerequisite for anything learned)
6. Only then: a tabular learned edge classifier, evaluated against the deterministic baseline
7. GNN/graph-transformer experimentation — explicitly deferred, revisit criteria stated above
